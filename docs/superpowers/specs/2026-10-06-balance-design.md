# Shape Siege 首关平衡调整方案

状态：已批准并实施于 0.8.0；原始调查基于 0.7.6 / b5964d9。以下保留调查与设计依据，最终验证见 docs/balance-validation.md。

## 问题与证据

首领在 240 秒出现、300 秒截止，生命 4800，意味着整个窗口必须维持至少 80 点有效每秒伤害。移动、躲避、复活和技能攻击小怪都会减少实际输出时间。

现有游戏已有连锁闪电、回旋刃、雷区、震荡波和落星等群攻；问题是早期拿到和强化它们不够稳定，基础伤害偏弱，而高压阶段持续加入大批敌人。追踪弹、飞刃等会优先攻击最近目标；落星优先密集群体，首领战的输出会分散。

使用真实 GameWorld、正常生命与 3 条命、合法选牌和自动普通技能，对三个角色各运行种子 20261006、73、991。走位脚本主动捡经验、避怪和危险区，能量满时手动触发大招。两组选牌使用相同走位算法；不是对真人胜率的估计。

| 选牌策略 | 圆形通关 | 正方形通关 | 三角形通关 | 总结果 |
| --- | --- | --- | --- | --- |
| 优先输出、范围技能与强化 | 3/3 | 3/3 | 3/3 | 9/9，260–286 秒通关 |
| 随机选择合法卡牌 | 1/3 | 0/3 | 1/3 | 2/9；6 次超时、1 次死亡 |
| 随机卡牌，仅把首领生命降至 3000 | 2/3 | 1/3 | 3/3 | 6/9；2 次超时、1 次死亡 |

随机选牌的六次超时时，首领剩余生命为 417–2219；可见敌人峰值最高 95，场上总敌人峰值最高 154。只降低首领生命未改变清怪压力，仍有两局超时，其中两局胜利发生在 297 秒，容错仍很小。

复现命令：`npm exec vitest run -- --config .superpowers/balance-probe.config.ts`。随机选牌增加 `BALANCE_POLICY=casual`；首领单变量实验再增加 `BALANCE_BOSS_HP=3000`。诊断文件在被 Git 忽略的 `.superpowers/`，不进入游戏和常规测试。记录为 `balance-baseline.json`、`balance-casual.json`、`balance-boss3000.json`。

## 路线比较

1. **组合调整，推荐**：保证早期群攻、改善攻击成长、降低高压刷怪、削弱首领并隔开首领战与普通怪潮。解决清场、构筑波动和首领窗口三个问题。
2. **只削弱敌方**：首领生命、刷怪量降低，改动小；现有卡池和基础攻击仍容易形成乏力构筑。单变量实验已经证明只降首领生命并不充分。
3. **只强化英雄**：基础与群攻伤害大幅提升，保留刷怪密度；能改善击杀，但小屏危险密度和后期数值膨胀仍需处理。

## 推荐规则

### 1. 稳定形成清场能力

- 保留三角色生命、移速、先天属性与主要定位，不继续堆生命。
- 正方形开局：四向冲击 + 连锁闪电。
- 圆形开局：星环轨道 + 震荡波。
- 三角形开局：穿透飞刃 + 回旋刃。
- 起手群攻占用现有普通技能槽，初始仍为 4 槽，不额外增加槽位。
- 前三次三选一选择，每次至少提供一张技能获取/升级/元素/行为等直接强化攻击的卡。重抽保留此保证；完成选择后才消耗一次保证，免费奖励也计入次数。保底项不足时用伤害强化兜底。
- 卡牌仍为三张不同选项，玩家可以选防御或功能牌；不强制玩家选输出。不改变战斗随机与选牌随机的独立性。

### 2. 让低等级攻击也能有效清怪

以下为第一轮待实测参数，不宣称已验证新平衡。实施时依据同一组回放结果作小幅修正，并在更新记录中写最终值。

| 技能 | 现值 | 拟调整 |
| --- | --- | --- |
| 四向冲击 | 伤害 18、冷却 1 秒 | 伤害 24、冷却 0.9 秒 |
| 星环轨道 | 伤害 15 | 伤害 20 |
| 穿透飞刃 | 伤害 24、冷却 0.75 秒 | 伤害 30、冷却 0.65 秒 |
| 连锁闪电 | 伤害 22、冷却 2 秒 | 伤害 30、冷却 1.8 秒 |
| 回旋刃 | 伤害 18、冷却 2 秒 | 伤害 24、冷却 1.8 秒 |
| 震荡波 | 伤害 24、半径 140、冷却 2.5 秒 | 伤害 36、半径 170、冷却 2.1 秒 |
| 地面雷区 | 伤害 35、半径 100 | 伤害 45、半径 120 |
| 落星 | 伤害 40、半径 90、冷却 2.8 秒 | 伤害 52、半径 120、冷却 2.4 秒 |
| 追踪弹 | 伤害 20 | 伤害 24 |

- 技能每级线性基础伤害增长由 12% 改为 16%，不是按级连乘。
- 伤害强化卡由 +3% 改为 +6%；UI 描述、升级前后数值与实际结算统一。
- 群攻范围绘制与判定读取同一配置。继续保留既有伤害冷却、命中次数和不递归元素规则。

### 3. 降低怪潮压力，同时保留成长速度

- 开局刷怪间隔乘 1.1、60–150 秒乘 1.2、150 秒至首领前乘 1.55；高压常规生成速率相对旧版约降低 35%。阶段批次数和敌人种类保留。
- 普通怪活跃上限从 250 降至 140；不是一次性删除现有敌人的机制。
- 重甲怪生命 115→90，阶段精英生命 1100/1400→800/1000；其他普通怪的生命和攻击伤害先保持。
- 击杀经验乘 1.25，避免少刷怪后升级变慢；用回放检查 240 秒的实际等级，不只比较理论经验。
- 保留现有事件、3 条命及复活机制。

### 4. 把首领战做成可读的战斗阶段

- 仍是 5 分钟一关，首领仍在 4:00 出现，5:00 截止，避免同时改时间轴。
- 首领基础生命 4800→3000；招式、伤害和预警保留。
- 首领成功入场时清退普通怪与入场前敌方弹丸，不发击杀经验、掉落、能量或吸血收益，不增加击杀统计；存活阶段/事件精英保留，奖励逻辑不变。
- 首领召唤间隔 20→25 秒，每批 10→4，活跃召唤上限 30→10。
- 首轮先保留现有技能选敌规则，避免把更好的自动瞄准与大量数值增强一次混在一起。如果回放显示普通构筑仍持续攻击杂兵、首领超时，再单独评估首领优先瞄准，不直接新增复杂机制。
- 下一关继续保留本局成长。精英/首领关卡生命倍率由每关 +50% 改为 +35%；普通怪倍率保留，至少验证前 3 关，防止首关改善后第二关立刻失衡。

## 实施范围与验证

沿用 config、director、world、progression、combat、现有渲染与 UI。新增参数集中配置，不替换引擎或架构，不新增技能槽类型、不引入联机。修改菜单的起手技能说明，以及相关升级文案。

验证要求：

- 三角色各三个相同种子，随机卡牌组每个角色至少 2/3 首关通过；优化组保持 9/9。脚本目标只是自动回归门槛，不代表真人通关率。
- 记录首领击杀时间、剩余生命/命数、240 秒等级、可见怪峰值；确认胜率提升不是单纯靠复活次数或过量治疗。
- 目标首关随机构筑首领战大多数在 25–50 秒内完成；超过 55 秒的胜利视为仍需改善的边缘结果。优化构筑允许更快，但连续 3 关不能变成一出现即秒杀。
- 检查起手槽位、卡牌保底与重抽、清退无奖励、首领与精英存活标记、下一关缩放等真实行为。
- 运行必要回归、完整测试、类型检查和生产构建；Chrome 桌面与手机尺寸检查新增说明及群攻效果。
- 按 SemVer 发布 0.8.0，更新 CHANGELOG、创建单一目的提交，推送 main 并等待 Pages 部署成功，验证线上版本。
- 原 .7.6 诊断失败不属于现有 89 项产品测试失败；实施结果见 `docs/balance-validation.md`。

## 风险与边界

同时降低刷怪与提高伤害可能让老玩家觉得过于容易，因此保留精英/首领招式，并用普通与优化两组回放、后续关卡一起评估。减少怪物会影响经验和大招充能，经验已有补偿，能量需要观察实际施放次数后再决定是否调整。

回放具有比真人更稳定的走位、对危险区的读取和选牌假设；不把 6/9 或 9/9 称为玩家胜率，也不据此宣称手机真机体验已经验证。

实施记录：保留提议数值。随机选牌回放首领战实际为 15–34 秒，快于原 25–50 秒目标；优先接受此次清场改善，后续按真人反馈继续微调。
